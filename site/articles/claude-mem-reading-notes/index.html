换个聊天窗口，AI 又忘了昨天改过什么

2026.11.144 分钟阅读

记忆存在外面的笔记柜里。下次开始工作，究竟先拿哪几张卡片出来？

“这个方案昨天已经试过了。”

和 AI 一起处理一个稍长的项目，这句话应该不难想象。上次为什么放弃某种做法、某个报错是怎么解决的，换一个会话，又得重新讲一遍。

当然，可以自己写一份项目笔记。但每天读了什么、改了什么、试过什么，靠人手动补记录也挺费劲。

Claude-Mem 尝试把这件事接过去：从 Agent 的工作过程里留下记录，整理成较短的观察和摘要，等下次会话需要时，再取出相关内容。它现在已经提供多种 Agent 的适配入口，名字里的 Claude 不代表全部使用范围。项目 README 介绍了支持情况。

记忆先存在外面

这里说的“记住”，发生在模型外部。

可以想象一个人每天换一张干净的办公桌，但桌边一直放着同一个笔记柜。新的一天开始，先取几张和今天任务有关的卡片，就不必全靠重新回忆。

Claude-Mem 的基础流程也有类似分工：在工作发生时收集信息，用一个观察过程整理记录，再把结果保存下来。新会话开始时，按项目提供一份紧凑的上下文。这里的“上下文”，就是这次交给 AI 参考的材料。官方架构说明 展示了这些部件的关系。

这不会把一个项目的经历直接训练进模型参数。离开这套记录和读取机制，模型也不会凭空拥有同样的项目记忆。

笔记从哪里来

项目通过 Hooks 接收 Agent 的事件。Hook 可以理解成一个预先约定的通知点：开始会话了、调用工具了、结束了，就通知相应的处理程序。

在 src/cli/hook-command.ts 里，能看到适配器先把不同平台的输入整理成共同格式，再交给事件处理器，最后把结果转换回平台需要的形式。对应源码 还专门处理了失败时怎样退出，尽量避免记笔记的环节把原本的工作卡住。

后面有一个本地 Worker，可以把它理解成后台值班的小服务。它接收事件、安排整理、提供搜索和上下文等接口。这个部件的入口是 src/services/worker-service.ts。

记录主要存进 SQLite。SQLite 是一种可以把数据库放在本地文件里的工具。项目把会话、观察记录、摘要等信息分开保存，也保留记录所属项目、发生时间等信息。数据库文档 可以看到具体组织方式。

先翻目录，再抽卡片

如果每次都把过去所有笔记塞给 AI，材料会越来越长。里面还可能混着几周前已经不用的方案。

Claude-Mem 在 README 中介绍了一条分步检索路线：先用 search 找到简短索引；需要了解前后经过时，再用 timeline；最后通过 get_observations 取选中的详细记录。

这有点像查一本书：先看目录，翻到那一节，再决定要不要往前多读两页。先给出的信息少一些，后面仍然留着回查详情的入口。

比如，假设记录里有一张卡片写着“菜单故障和某个事件处理有关”。它可以帮我们找到上次调查的位置。但真正要改代码时，仍然应该打开现在的文件，看看相关逻辑有没有被后来的修改替换掉。

记忆可以提供线索，旧结论有没有过期，还得再判断。

顺着一条笔记读源码

这次阅读时，我给自己留的路线很短：

src/cli/ 接收事件 → src/services/worker/ 处理 → src/services/sqlite/ 保存 → src/services/context/ 组织下次要带上的内容。

每经过一处，都可以问同一个问题：“上一环节交过来的内容，在这里变成了什么？”这样比一口气研究所有配置容易跟住。

对我来说，这个项目最有意思的地方是它怎样挑选信息。记下所有东西不难理解，真正影响使用体验的，往往是下次打开聊天时，究竟先拿哪几张卡片出来。
